Contech-X 사용자 매뉴얼

1화면구성 기본

Contech-X는 상단 작업 메뉴, 좌측 프로젝트/공정 탐색, 중앙 작업 영역, 우측 보조 패널을 기준으로 사용합니다. 처음에는 현재 선택한 프로젝트와 공정표가 어디인지 확인한 뒤 작업을 시작합니다.

주요 영역

내 메모

개인 작업 메모를 남겨 화면 전환 후에도 확인합니다.

워크스페이스

회사/프로젝트 맥락을 바꾸는 기준 영역입니다.

매뉴얼

기능 사용법을 별도 화면에서 확인합니다.

프로필

사용자 정보와 권한, 계정 메뉴를 확인합니다.

2EPS PRJ 구조

EPS는 프로젝트를 담는 상위 분류입니다. 그룹사 조직, 본부, 현장 같은 관리 단위를 먼저 정리하고 그 아래 프로젝트를 배치하면 공정표를 찾기 쉽습니다.

EPS와 PRJ EPS는 프로젝트 보관함, PRJ는 실제 현장/사업 프로젝트입니다. 공정표는 PRJ 안에서 만들어집니다.
구분 P6 Contech-X
공정표 구조 일반적으로 한 프로젝트에 하나의 공정표를 운용 한 프로젝트 안에서 여러 공정표를 함께 운용
활용 예 단일 기준 공정표 중심 관리 전체 공정, 동별 공정, 협력사 공정 등 멀티 공정표 관리

3프로젝트 및 공정표 생성

프로젝트 생성 및 멤버 추가

새 프로젝트는 프로젝트 코드, 프로젝트 이름, 현장 주소, 발주처/시공사, 계획 시작/종료일을 입력해 만듭니다. 생성 후 멤버를 추가해야 팀원이 프로젝트와 공정표를 함께 볼 수 있습니다.

공정표 생성

프로젝트 안에서 공정표를 추가합니다. 공정표명과 기준일을 명확히 쓰면 여러 공정표를 운용할 때 혼동을 줄일 수 있습니다.

타 프로그램 공정파일 불러오기

MS Project에서 작성한 공정표는 XML 파일로 저장한 뒤 Contech-X로 불러올 수 있습니다. 불러온 공정표는 프로젝트 안의 공정표로 생성되며, 이후 WBS, Activity, 관계, 일정 정보를 Contech-X 화면에서 이어서 편집합니다.

P6 파일 불러오기 개발 예정 Primavera P6 공정파일 불러오기는 추후 개발 예정입니다. 현재는 MS Project XML 파일 불러오기를 사용합니다.

4WBS 생성, WBS 노드 인터페이스

WBS Work Breakdown Structure. 공사를 작은 작업 묶음으로 나누는 뼈대입니다. 예: 공사 전체 > 지하층 > 골조공사 > 철근 배근.

WBS 노드 인터페이스와 공정 라이브러리

WBS 노드는 공정표의 목차입니다. 노드를 먼저 만들고, 각 노드 아래에 실제 작업(Activity)을 배치하면 일정과 담당 범위가 명확해집니다.

스프레드시트 WBS

표 형태로 WBS와 작업을 빠르게 입력합니다. 엑셀처럼 행 단위로 복사, 수정, 정렬하기 좋습니다.

5작업간 관계설정

Activity 공정표에서 실제 일정 계산 대상이 되는 작업입니다. 시작일, 종료일, 기간, 선후행 관계를 가집니다.

작업 관계는 선행 작업이 후속 작업에 어떤 영향을 주는지 정하는 규칙입니다. 관계가 정확해야 스케쥴링 결과도 믿을 수 있습니다.

관계 뜻 예시
FS Finish to Start. 선행 작업이 끝나야 후속 작업 시작 철근 배근 완료 후 콘크리트 타설 시작
FF Finish to Finish. 두 작업의 완료 시점이 연결 검측 완료와 보완 작업 완료를 같은 완료 기준으로 관리
SS Start to Start. 선행 작업이 시작되면 후속 작업도 시작 가능 먹매김 시작 후 자재 양중 준비 시작
Lag / Lead Lag는 기다리는 시간입니다. FS + 2일이면 선행 작업 종료 후 2일 뒤 시작합니다. Lead는 당겨 시작하는 시간입니다. FS - 1일이면 선행 작업 완료 1일 전부터 후속 작업을 시작하도록 계획합니다.

6캘린더 설정

캘린더는 작업일과 휴무일을 정하는 기준입니다. 같은 기간 5일 작업과 6일 작업은 종료일이 달라지므로, Activity 성격에 맞는 캘린더를 지정해야 합니다.

멀티 캘린더 현장 기본 캘린더, 장비 작업 캘린더, 야간 작업 캘린더처럼 여러 작업 기준을 분리해 관리합니다.
  1. 현장 기본 작업일과 휴무일을 먼저 설정합니다.
  2. 특정 공종이나 작업 조건이 다르면 별도 캘린더를 만듭니다.
  3. Activity에 알맞은 캘린더를 지정합니다.
  4. 스케쥴링 후 종료일이 의도와 맞는지 검증합니다.

7스케쥴링 및 검증

스케쥴링은 작업 기간, 캘린더, 선후행 관계를 계산해 전체 일정표를 다시 배치하는 기능입니다. 관계가 누락되면 계산 결과가 실제 흐름과 달라질 수 있습니다.

Critical Path

프로젝트 종료일을 직접 결정하는 작업 흐름입니다.

Float / FT

전체 종료일을 늦추지 않고 작업이 움직일 수 있는 여유일입니다.

검증 기준 선후행 없는 작업, 비정상 기간, 캘린더 누락, Critical Path 변화는 스케쥴링 후 반드시 확인합니다.

8베이스라인 개발중

베이스라인은 검토가 끝난 공정표의 계획 상태를 저장해 이후 현재 계획 및 실적과 비교하는 기준입니다. 공정표를 변경하기 전에 베이스라인을 만들면 시작일·완료일과 일정 차이를 기준 계획과 비교할 수 있습니다.

Baseline 특정 시점의 공정표를 보존한 기준 계획입니다. 베이스라인을 만든 뒤 현재 공정표를 수정해도 저장된 기준 계획은 그대로 유지됩니다.

사용 순서

  1. 공정표 저장·검증
  2. 베이스라인 추가
  3. Primary 배정 확인
  4. 기준 막대·편차 확인
시작하기 전 작업 기간·관계·캘린더를 확인하고 스케쥴링 결과를 저장합니다. 저장되지 않은 작업·관계·자원 변경이 있으면 베이스라인 추가와 복사가 제한됩니다.

1. 베이스라인 관리 열기

  1. 1상단 도구모음의 BL(베이스라인) 버튼을 누릅니다.
  2. 2베이스라인 관리…를 선택합니다.

2. 현재 공정표를 베이스라인으로 저장

  1. 1현재 공정표 이름과 기준일이 맞는지 확인합니다.
  2. 2Project·Primary·Secondary·Tertiary의 현재 배정 상태를 확인합니다.
  3. 3목록이 비어 있으면 추가를 누릅니다.
  1. 1현재 공정표를 복사하여 저장: 지금 저장된 공정표를 읽기 전용 기준 계획으로 보존합니다.
  2. 2다른 공정표를 베이스라인으로 전환: 대상 공정표가 있을 때만 선택할 수 있으며, 복원 전까지 일반 공정표 목록에서 숨겨집니다.
  3. 3구분하기 쉬운 베이스라인 이름과 최초 계획·관리 기준·What-if 등의 유형을 지정합니다.
  4. 4복사를 누릅니다. 생성된 베이스라인은 Primary에 자동 배정됩니다.

3. 생성 결과와 배정 확인

  1. 1Primary에 새 베이스라인이 배정됐는지 확인합니다. 슬롯 드롭다운을 바꾸면 즉시 저장됩니다.
  2. 2목록 행의 1 배지는 해당 베이스라인이 Primary 슬롯에 배정됐다는 뜻입니다.
  3. 3선택한 베이스라인을 열기·복사·삭제·복원할 수 있습니다.
  4. 4이름과 유형을 수정한 뒤 정보 저장을 누르고, 생성 방식·작업 수·추가일·배정 슬롯을 확인합니다.

배정 슬롯의 의미

  • 프로젝트: 프로젝트의 공식 기준 및 집계에 사용할 베이스라인
  • Primary: 현재 공정표의 간트 기준 막대와 비교 컬럼에 사용할 베이스라인
  • Secondary / Tertiary: 추가 비교 기준을 보관하는 선택 슬롯
  • —: 해당 슬롯의 배정을 해제

4. 기준 막대와 일정 차이 확인

  1. 1BL 버튼에 마우스를 올리면 현재 Primary 이름이 표시됩니다.
  2. 2기준 막대 표시의 체크로 간트 기준 막대를 켜고 끕니다. 비교 해제는 Primary 배정을 제거합니다.
  3. 3간트에서 현재 막대와 기준 막대를 비교합니다. 생성 직후에는 날짜가 같아 두 막대가 겹쳐 보입니다.
확인 위치의미
BL TF베이스라인 저장 당시 일정과 관계로 계산한 Total Float
기준 시작 / 기준 완료Primary 베이스라인에 저장된 시작일과 완료일
기준 차이현재 완료일과 기준 완료일의 차이. 양수는 기준보다 늦고, 음수는 빠르며, 0일은 동일
간트 기준 막대현재 막대와 기준 계획을 시각적으로 비교. 날짜가 같으면 서로 겹침
현재 비교 표시 기준 간트 막대와 기준 컬럼에는 Primary 베이스라인이 표시됩니다. Secondary와 Tertiary는 배정값을 저장하지만, 현재 화면에서 세 기준 막대를 동시에 표시하지는 않습니다.

관리 기능

기능동작주의사항
열기선택한 베이스라인을 읽기 전용 공정표로 확인기준 계획을 직접 수정하지 않음
복사선택한 베이스라인의 복사본 생성저장되지 않은 현재 공정표 변경이 있으면 제한됨
삭제선택한 베이스라인을 영구 삭제비교 중인 베이스라인이면 Primary 비교도 함께 해제됨
복원베이스라인을 편집 가능한 공정표로 되돌림복원 후 베이스라인 관리 목록에서 사라짐
삭제와 복원 구분 다른 공정표를 베이스라인으로 전환한 경우 삭제하면 원래 공정표도 복구할 수 없습니다. 다시 편집하려면 복원을 선택합니다.

9자원관리 개발중

자원관리는 작업에 필요한 인력, 장비, 자재를 연결해 투입 계획을 보는 기능입니다. 일정만 보는 공정표에서 한 단계 더 나아가 실제 수행 가능성을 확인합니다.

  • 인력: 직종, 투입 인원, 투입 기간 관리
  • 장비: 장비 종류, 사용 기간, 중복 투입 확인
  • 자재: 필요 수량, 반입 시점, 작업 연결 관리

10작업(Activity) 상세기능

상세 작업설정 개발중

Activity별 작업명, 기간, 담당자, 캘린더, 관계, 자원 정보를 세부 설정합니다. 상세 정보가 정확할수록 스케쥴링과 실적 분석 품질이 좋아집니다.

필터링 기능 개발중

공종, 담당자, 기간, 지연 여부, Critical 여부 등 조건으로 작업을 좁혀 필요한 작업만 빠르게 확인합니다.

공정표 필터보기 개발 예정 P6의 기본 필터 기능처럼 전체 공정표에서 필요한 작업만 골라 보는 기능입니다. 특정 기간, 특정 WBS, 작업명/코드 키워드를 기준으로 Activity를 필터해 현재 검토해야 할 공정만 빠르게 확인합니다.
  • 기간 필터: 이번 주, 이번 달, 지정 시작일/종료일 범위 작업만 표시
  • WBS 필터: 선택한 WBS 노드와 하위 작업만 표시
  • 키워드 필터: 작업명, 코드, 담당자 등 텍스트 조건으로 검색

O/D 일수고정, 계산일수

O/D는 Original Duration, 최초 계획 기간입니다. 일수고정은 사용자가 입력한 기간을 유지하는 방식이고, 계산일수는 캘린더와 관계를 반영해 시스템이 산정하는 기간입니다.

11조직도 OBS 작성

OBS Organization Breakdown Structure. 프로젝트의 조직 단위와 구성원 관계를 계층으로 표시하는 조직도입니다.

OBS는 프로젝트 참여 조직을 사용자가 한눈에 확인하도록 표시합니다. WBS 또는 Activity의 수정 책임과 프로젝트 권한을 결정하는 화면은 아닙니다.

OBS 조직도 작성

  1. 프로젝트 조직 단위를 만듭니다.
  2. 부서, 협력사, 구성원을 계층으로 정리합니다.
  3. 확대·축소·접기 기능으로 조직 구조를 확인합니다.

권한 관리 위치 개발중

프로젝트 조회·수정 권한과 역할은 OBS가 아니라 프로젝트 멤버 화면에서 관리합니다. 프로젝트 총괄이 멤버 구성과 역할을 관리합니다.

12공정 라이브러리 편집 개발중

공정 라이브러리 편집은 반복 사용 가능한 표준 데이터를 관리하는 곳입니다. 현장마다 같은 내용을 다시 만들지 않도록 라이브러리화합니다.

  • 표준공정 라이브러리: 자주 쓰는 WBS와 Activity 묶음
  • 자원 라이브러리: 인력, 장비, 자재 표준 목록
  • 멀티 캘린더 라이브러리: 현장별 작업일 기준 템플릿

13PDF 출력

PDF 출력은 공정표의 WBS 시트와 간트를 출력용 문서로 구성한 뒤 프린터로 인쇄하거나 PDF 파일로 저장하는 기능입니다. 출력 옵션을 정한 다음 앱 내부 미리보기에서 제목과 표시 문구를 다듬고, 마지막에 브라우저 인쇄 창을 사용합니다.

사용 순서

  1. PDF 출력 열기
  2. 출력 옵션 설정
  3. 미리보기 편집·확인
  4. 인쇄 또는 PDF 저장
출력용 임시 원고 앱 내부 미리보기에서 바꾼 제목·컬럼명·작업명은 이번 출력에만 사용됩니다. 원본 공정표와 Activity 데이터는 변경되지 않으며, 미리보기를 닫으면 편집 내용도 사라집니다.

1. PDF 출력 열기

  1. 1상단 도구모음의 PDF 출력 버튼을 누릅니다.

2. 출력 옵션 설정

  1. 1용지·행 높이·배율을 정합니다. 기본 권장값은 A3 가로, 보통, 100%입니다.
  2. 2타임스케일을 정합니다. 자동은 전체 기간을 한 페이지 폭에 맞추고, 월·주·일은 고정 눈금을 사용합니다.
  3. 3출력 기간을 직접 지정하거나 전체 기간을 선택합니다.
  4. 4WBS 범위와 펼침 수준을 정합니다. 전체 공정 또는 특정 WBS 하위만 출력할 수 있습니다.
  5. 5시트 컬럼과 의존관계 연결선 표시 여부를 선택합니다. Activity 컬럼은 필수입니다.
  6. 6설정이 끝나면 미리보기를 누릅니다.
옵션설정 기준
용지A3 가로 또는 A4 가로. 넓은 간트와 여러 컬럼은 A3 가로를 권장
행 높이·배율행이 많으면 압축 또는 낮은 배율을 사용. 한 페이지에 더 많이 표시되지만 글자도 작아짐
타임스케일자동은 전체 기간을 한 페이지 폭에 맞춤. 월·주·일은 기간이 길면 가로 페이지가 추가됨
출력 기간보고 대상 기간만 지정하거나 전체 기간 선택
WBS 범위·펼침전체 공정 또는 선택 WBS 하위와 화면 그대로·1~4단계·전체 펼침 중 선택
시트 컬럼보고서에 필요한 컬럼만 선택. Activity 컬럼은 항상 포함

3. 앱 내부 편집 미리보기

미리보기는 실제 인쇄 페이지와 같은 구조로 표시됩니다. 점선 테두리가 있는 글자를 클릭하면 이번 출력에 사용할 문구를 직접 수정할 수 있습니다.

  1. 1점선으로 표시된 문서 제목과 공정표 부제목을 클릭해 출력용 문구를 수정합니다.
  2. 2초기화는 진입 시 문구로 되돌리고, 닫기는 원본을 바꾸지 않고 미리보기를 종료하며, 인쇄는 브라우저 인쇄 창을 엽니다.
  1. 1문서 제목을 바꾸면 표지와 각 본문 페이지의 제목에 함께 반영됩니다.
  2. 2컬럼 제목을 보고서 용어에 맞게 수정할 수 있습니다.
  3. 3Activity 이름을 수정하면 같은 행의 시트와 간트 막대 문구에 함께 반영됩니다.
편집 가능편집되지 않는 원본 정보
문서 제목, 공정표 부제목WBS 계층과 행 순서
시트 컬럼 제목시작일·완료일·기간·진척률

4. 브라우저에서 인쇄 또는 PDF 저장

  1. 앱 내부 미리보기 오른쪽 위의 인쇄를 누릅니다.
  2. 브라우저 인쇄 창의 대상에서 프린터 또는 PDF로 저장을 선택합니다.
  3. 앱에서 선택한 A3/A4와 같은 용지 크기 및 가로 방향인지 확인합니다.
  4. 필요하면 브라우저의 머리글·바닥글을 끄고 최종 미리보기를 확인한 뒤 인쇄하거나 저장합니다.
PDF 기본 파일명 미리보기에서 수정한 문서 제목과 부제목을 기준으로 기본 파일명이 제안됩니다. 실제 표시 형식과 사용할 수 있는 문자는 브라우저와 운영체제에 따라 달라질 수 있습니다.
최종 출력 확인 브라우저 인쇄 창에서 배율을 다시 바꾸면 앱에서 정한 배율과 중복 적용될 수 있습니다. 페이지 잘림, 글자 크기, 용지 방향과 머리글·바닥글을 확인한 뒤 저장합니다. 인쇄를 취소하면 앱 내부 미리보기로 돌아오며, 미리보기를 닫기 전까지 편집 문구는 유지됩니다.

출력 페이지 구성

  • 첫 페이지에는 문서 제목, 공정표 이름, 공정 기간, Data Date와 출력일이 표시됩니다.
  • 본문 페이지에는 선택한 WBS 시트와 간트가 함께 표시되고 페이지마다 헤더가 반복됩니다.
  • 행이 많으면 세로 페이지가 추가되고, 고정 타임스케일의 기간이 길면 가로 페이지도 추가됩니다.

14자원 실적입력 개발중

자원 실적입력은 계획 대비 실제 투입된 인력, 장비, 자재를 기록하는 기능입니다. 시간대별 투입 자원을 관리하면 생산성 분석과 비용 추적에 활용할 수 있습니다.

  • 일자/시간대별 투입 인원 기록
  • 장비 사용 시간 기록
  • 자재 반입 및 사용량 기록

15EVMS와 S-Curve 개발중

EVMS Earned Value Management System. 계획, 실적, 투입 비용을 비교해 프로젝트 성과를 관리하는 방식입니다.
S-Curve 누적 진척률이나 누적 비용을 시간 흐름에 따라 그린 곡선입니다. 계획 곡선과 실적 곡선을 비교하면 지연과 초과 투입을 빠르게 볼 수 있습니다.
본 매뉴얼은 현재 제공된 화면 이미지와 개발 상태를 기준으로 작성되었습니다. 개발중 기능은 실제 배포 시점에 명칭과 동작이 바뀔 수 있습니다.
